## 1. PROJECT OVERVIEW

**MAREFIYAYE** is a full-stack SaaS marketplace for renting homes in Ethiopia. It supports **two rental modes on one platform**:

| Mode | Pricing unit | Target user |
|---|---|---|
| **Short-term** | Per night | Tourists, business travelers, weekend stays |
| **Long-term** | Per month | Expats, students, locals relocating |

**Core value proposition:** *"Verified properties, manual bank payment, zero broker fees."*

**Primary actors:**
- **Guest** — browses, books, pays via manual bank transfer, uploads receipt
- **Host** — creates listings, awaits admin approval, manages bookings
- **Admin / Super Admin** — full God mode over everything

**Current platform state:**
- Backend: fully operational, all endpoints tested end-to-end (booking → payment → verify → confirmed)
- Frontend: public site + auth + guest dashboard + host dashboard working
- Admin panel: overview, moderation (listings/hosts/payments/bookings/users), bank accounts, banners done. **Broadcasts page needs rebuild.**
- Full i18n (EN + AM) with modular per-namespace files, cookie persistence, admin-editable amenities/property-types lists via config
- Manual bank payment workflow fully implemented with admin verification queue

## 2. MONOREPO & TECH STACK (LOCKED — DO NOT CHANGE)

### Package manager
- **npm workspaces** (not pnpm, not yarn)
- Root `package.json` has `workspaces: ["apps/*", "packages/*"]`
- `apps/web`, `apps/api`, `packages/shared` are the three workspaces

### JavaScript only
- **No TypeScript** — every file is `.js` or `.jsx`
- **No Prisma** — raw SQL with `pg` (node-postgres)
- API files use `.js` extensions in import paths (Node ESM)
- Web files use `.jsx` extensions explicitly

### Apps

**`apps/web` — Next.js 15.5**
- App Router
- React 19
- Tailwind CSS 3.4 (NOT v4)
- `next/font/google` for fonts (self-hosted, no CDN)
- `next/image` for image optimization
- Path alias: `@/*` maps to `apps/web/src/*` (jsconfig.json)
- Server Components + Client Components (`'use client'` when needed)

**`apps/api` — Express 4**
- Runs as Express 4 (Node ESM)
- Serverless entry via `serverless-http` (Vercel Pattern A)
- Dev entry: `apps/api/src/server.js` (nodemon watches changes)
- Serverless entry: `apps/api/index.js`
- Path alias: relative imports only

**`packages/shared` — pure JS package**
- Name: `@marefiyaye/shared`
- Zero runtime dependencies
- Contains: constants, validators (Zod), formatters, config schema, i18n dictionary builder + all locale files
- Imported by both `apps/api` and `apps/web`
- **Critical rule:** no `.json` files in shared — everything is `.js` with named exports

### Deployment
- **Pattern A — single Vercel project**
- `apps/web/src/app/api/v1/[...path]/route.js` — catch-all handler that imports the Express app via `serverless-http` and forwards every `/api/v1/*` request to it
- In local dev, frontend fetches API directly at `http://localhost:5000` (via `apps/web/src/lib/env.js` which resolves `NEXT_PUBLIC_API_BASE_URL` differently for dev vs prod)

### Database
- **PostgreSQL on Neon** (free tier)
- Raw SQL migrations tracked in `schema_migrations` table with checksums
- Connection pool: **max 5 connections** (Neon free tier limit — see `apps/api/src/db/pool.js` — has retry logic + pool warmup for cold starts)
- SSL enforced: `sslmode=require`

### Auth
- **Roll-your-own JWT** (no Auth.js, no NextAuth)
- Access token: 15 min (dev currently set to 24h to avoid re-login churn — **must revert to 15m for production**)
- Refresh token: 7 days, stored hashed (SHA-256) in `refresh_tokens` table
- Transport: **httpOnly cookies**
  - `mrf_access` — path `/`
  - `mrf_refresh` — path `/api/v1/auth`
- Impersonation supported — access token carries `impersonatedBy: adminId` claim
- RBAC middleware: `requireAuth`, `requireRole`, `requireAdmin`, `requireSuperAdmin`
- `forbidImpersonation` middleware blocks sensitive actions while impersonating

### Storage
- **Cloudinary** for all image uploads (listings + payment receipts)
- Signed upload flow:
  1. Client → `POST /api/v1/uploads/sign` { category }
  2. Server validates clock skew (against DB's NOW()), returns signed params
  3. Client → POST directly to Cloudinary with the file + params
  4. Cloudinary → returns `{ secure_url, public_id }`
  5. Client → submits those to the API in the booking/listing payload
- Cloudinary creds in `.env.local` (`CLOUDINARY_CLOUD_NAME`, `_API_KEY`, `_API_SECRET`, `_FOLDER`)

### Icons
- `lucide-react` only

### Fonts
- `Plus Jakarta Sans` (Latin) + `Noto Sans Ethiopic` (Amharic)
- Loaded via `next/font/google` in `apps/web/src/app/layout.jsx`

### Styling architecture (very important)
3-layer system to avoid Tailwind vs custom-CSS conflict:

1. **`styles/tokens.css`** — CSS custom properties for all design values:
   - Colors (brand, neutral scale, semantic `--color-bg/fg/muted/border/ring`)
   - Radii (`--radius-sm/md/lg`)
   - Shadows (`--shadow-card/search/modal`)
   - Motion (`--duration-fast/normal/slow`, `--ease-out`)
   - Fonts (`--font-sans`, `--font-ethiopic`)
   - **Color format is space-separated RGB** (e.g. `150 75 0`) not hex — because Tailwind uses `rgb(var(--token) / <alpha-value>)` pattern

2. **`tailwind.config.js`** — maps Tailwind utilities to token vars:
   - `colors.brand.500 = 'rgb(var(--color-brand-500) / <alpha-value>)'`
   - `colors.bg/fg/muted/border/ring` = semantic tokens
   - `borderRadius.sm/md/lg`, `boxShadow.card/search/modal`
   - `fontFamily.sans` reads `var(--font-sans)`

3. **`styles/components.css`** — only ~50 lines of handwritten CSS for:
   - `.scrollbar-thin`, `.scrollbar-hide` (WebKit pseudo-elements)
   - `.animate-fade-up`, `.animate-fade-in`, `.animate-slide-in-right`, `.animate-scale-in` (keyframes)
   - Focus ring polish

**Dark mode:** toggled via `.dark` class on `<html>`; `--color-*` variables override in `.dark {}` block inside `tokens.css`. Persisted in localStorage, respects system preference.

**Rule:** NEVER write raw hex in JSX. Use Tailwind utility or CSS var only.

### Animations
- Allowed keyframes: `fade-up`, `fade-in`, `scale-in`, `slide-in-right`
- Durations from tokens
- Respect `prefers-reduced-motion` (not yet wired — pending)

## 3. DESIGN DECISIONS (locked)

### Language & i18n
- **English (en) + Amharic (am)** supported today
- Structure: `packages/shared/src/i18n/locales/<lang>/<namespace>.js`
- **Keys are flat dotted strings** — e.g. `auth.login.title`, `booking.checkout.amount`
- Adding a new language = add `LANGUAGES` entry + create `locales/<code>/*.js` files
- No `next-intl`, no `react-i18next` — custom `I18nContext` uses `getTranslator(lang)` from `@marefiyaye/shared/i18n`
- **NEVER display hardcoded strings in UI** — everything is a key
- **Never use JSON locale files** — always `.js` default exports
- i18n has a `preloadDictionaries()` function that must be called at API boot and in root layout before any `getTranslator()` call
- `getTranslator()` is **synchronous** and throws if dict not loaded. Async variant is `getTranslatorAsync()`
- Detected language priority: cookie `mrf_lang` → Accept-Language header → default `en`

### Auth strategy
- JWT (not sessions)
- Access token 15m in prod
- Refresh token in httpOnly cookie, rotating
- Impersonation = admin issues a token for another user, `impersonatedBy` claim present
- All auth middleware rejects with `AppError` and i18n keys

### Payments — manual bank transfer only
- Guest books → booking created with status `pending_payment`
- Guest transfers money outside platform → uploads receipt via Cloudinary
- Guest submits payment → payment status `under_review`, booking status `payment_review`
- Admin opens `/admin/payments` → views receipt thumbnail → verifies or rejects
- Verified → payment `verified`, booking `confirmed`, commission frozen on booking row
- Rejected → payment `rejected` with reason, booking back to `pending_payment` for retry
- **Commission is resolved at confirmation time** from `settings.commission.default_rate` or listing override, then **frozen** on the booking row (`commission_rate` + `commission_amount` columns) for historical accuracy

### Role model
- `guest` (default for new signups)
- `host` (promoted after creating host profile — `hosts` table row exists)
- `admin`
- `super_admin` (bootstrap admin from env)
- **Role is on `users.role`, but host existence is checked via `hosts` table** — a user can be `guest` role but have a `hosts` row. This is important: `ProfileMenu` uses `/host/me` to decide whether to show "Become a host" or "Host dashboard"

### Notification strategy
- **In-app notifications only** (no email, no SMS, no push yet)
- Stored in `notifications` table with i18n keys + interpolation params — rendered in user's preferred language on read
- Frontend polls `GET /me/notifications?limit=1` every 30s for unread count

### File uploads
- All images → Cloudinary with signed uploads
- Max 5MB per image
- Allowed formats: `jpg`, `jpeg`, `png`, `webp`
- Multiple uploads supported per listing (max 10)
- **Image reordering** supported in `ImageUploader` (drag + arrow buttons)

### Settings / God panel
- Every admin-configurable value is a row in `settings` table
- Schema declared in `packages/shared/src/config/schema/*.js`
- Categories: `general`, `commission`, `payment`, `features`, `theme`, `booking`, `seo`
- **Settings are validated** against Zod-like validators declared in schema
- Public settings exposed via `GET /config/public` (unauthenticated)
- Full settings via `GET /config/admin` (requires `requireAdmin`)
- Update via `PATCH /config/admin/:key` — **NOT `/admin/config/:key`** (this was a bug we fixed)
- **Editable lists (amenities, property types) are stored as `array` settings** with `{ value, icon?, label_en, label_am }` shape — edited via custom chip editor UI, NOT raw JSON

### File/folder conventions
- **Components:** plural folders for domains that have many files: `components/ui/`, `components/layout/`, `components/listings/`, `components/bookings/` (NOTE: booking widgets live in `components/booking/` singular — inconsistency we accept for now), `components/admin/`, `components/upload/`
- **Admin pages:** `apps/web/src/app/(admin)/admin/<feature>/page.jsx` with `<feature>/_<Feature>Client.jsx` for the client component
- **Public pages:** `apps/web/src/app/(main)/<feature>/page.jsx` with `<feature>/_<Feature>Client.jsx`
- **Auth pages:** `apps/web/src/app/(auth)/<login|register>/page.jsx` — these DON'T get header/footer (split-screen layout)
- **Route groups:** `(main)`, `(auth)`, `(admin)` — parentheses are not part of URL
- **Client components are prefixed with `_`** in the route folder (e.g. `_StaysClient.jsx`) — kept out of routing
- **API models:** `apps/api/src/models/<resource>.model.js`
- **API services:** `apps/api/src/services/<resource>.service.js`
- **API controllers:** `apps/api/src/controllers/<resource>.controller.js`
- **API routes:** `apps/api/src/routes/<resource>.routes.js`

### Component naming
- `Button`, `Input`, `Modal`, `Card` — UI primitives
- `_StaysClient`, `_HomeClient`, `_BankAccountsClient` — page-scoped client shells
- Compound components use dot notation: `Card.Header`, `Card.Title`, `Card.Content`, `Card.Footer`

### API versioning
- All routes under `/api/v1/`
- Response envelope: `{ success: true, data: {...}, meta?: {...} }` for success
- Error envelope: `{ success: false, error: { code, message, field?, details? } }` for failure
- `message` is always an i18n key or plain string — frontend translates i18n keys via `t()`

## 5. CRITICAL BUGS & GOTCHAS DISCOVERED

This section is the most valuable for continuation. Everything here was discovered the hard way.

### 🚨 BUG #1 — Inputs lose focus after 1-2 keystrokes inside `<Modal>`

**Symptom:** When typing in a form field inside a modal, only 1-2 characters appear, then the field stops accepting input. Focus is lost. To type more, the admin must click again.

**Root cause:** The `Modal`, `Input`, and `Button` primitives from `components/ui/` cause **remounting** of the input subtree on every keystroke. Even though `Modal` was refactored to persist the portal (via `display: none` instead of `return null`), the bug persisted.

**Confirmed via test:** Replacing an entire page with **raw HTML inputs/buttons/overlays** (no imports from `components/ui/`) makes the bug disappear.

**Current workaround (in use across the admin panel):**
- **Every admin page with a form or modal** uses **raw HTML `<input>`, `<textarea>`, `<select>`, `<button>`, `<div className="fixed inset-0 ...">`** instead of the primitives
- **Do NOT use `components/ui/Modal` or `components/ui/Input` in admin modals**
- **Do NOT use `useConfirm()` in admin modals** — use native `window.confirm()` for simple yes/no
- This pattern has been verified working across: bank accounts, banners, broadcasts (soon), listings moderation, hosts verification, users suspension

**Files using the raw-HTML pattern (all verified focus-safe):**
- `apps/web/src/app/(admin)/admin/bank-accounts/_BankAccountsClient.jsx`
- `apps/web/src/app/(admin)/admin/banners/_BannersClient.jsx`
- `apps/web/src/app/(admin)/admin/listings/_ListingsAdminClient.jsx`
- `apps/web/src/app/(admin)/admin/hosts/_HostsAdminClient.jsx`
- `apps/web/src/app/(admin)/admin/users/_UsersAdminClient.jsx`

**To be converted to raw-HTML pattern:**
- `apps/web/src/app/(admin)/admin/broadcasts/_BroadcastsClient.jsx` (needs full rebuild)
- `apps/web/src/app/(admin)/admin/settings/page.jsx` — the `SettingsForm.jsx` component uses primitives and likely has the same bug

**Future work:** find the actual root cause in `Button`/`Input`/`Modal` and fix at source so we can use primitives again.

**Strong suspect:** `Button` is `forwardRef` + may have internal state or unstable `key`. Investigate after the broadcast feature ships.

### 🚨 BUG #2 — Cloudinary 400 "Invalid Signature" (RESOLVED — was clock skew)

**Root cause:** Windows system clock was 30 days ahead. Cloudinary rejects signatures whose timestamp is >1 hour off from their server time.

**Fix applied:**
- User synced Windows clock manually (was the actual fix)
- `cloudinary.service.js` now has `assertClockIsSane()` that queries `SELECT EXTRACT(EPOCH FROM NOW()) * 1000` and rejects signature generation if drift > 10 minutes
- Also surfaced Cloudinary's actual error message in `ImageUploader.jsx` so future failures are debuggable

**Note:** system clock skew will break this again if user changes machine/date. Always verify `node -e "console.log(Date.now())"` returns a plausible timestamp (10 digits starting with 1.79 for 2026).

### 🚨 BUG #3 — Neon DB cold-start timeouts (RESOLVED — pool hardening)

**Symptom:** Every query takes 10+ seconds then times out. All endpoints return 500.

**Root cause:** Neon free tier aggressively closes idle connections. Our pool config (`poolMax: 10`) exceeded Neon's per-project connection cap under cold start.

**Fix applied in `apps/api/src/db/pool.js`:**
- `SAFE_POOL_MAX = 5` (regardless of env `DATABASE_POOL_MAX`)
- `SAFE_POOL_MIN = 1`
- `SAFE_CONNECTION_TIMEOUT_MS = 15_000`
- `SAFE_IDLE_TIMEOUT_MS = 10_000`
- `SAFE_STATEMENT_TIMEOUT_MS = 30_000`
- `keepAlive: true`
- `healthCheck()` retries 3× with 1s backoff
- `warmup()` runs `SELECT 1` on boot so first real request is fast
- `query()` retries once on transient errors (connection reset, timeout, etc.)
- `withTransaction()` retries the whole transaction on transient errors

**Server boot order in `apps/api/src/server.js`:**
1. `healthCheck()` (must pass)
2. `warmup()`
3. `preloadDictionaries()`
4. `app.listen()`

**If queries still time out:** it's the user's internet, not the code. Confirmed on 2026-11-04.

### 🚨 BUG #4 — i18n dictionary not loaded on auth pages (RESOLVED)

**Symptom:** `/login` throws `Dictionary for "en" is not loaded` in server component.

**Fix:** `RootLayout` calls `await preloadDictionaries()` before rendering. `login/page.jsx` and `register/page.jsx` use `getTranslatorAsync(DEFAULT_LANGUAGE)` instead of sync `getTranslator()`.

### 🚨 BUG #5 — API config PATCH path was wrong

**Symptom:** Settings save returns 404.

**Wrong path:** `/api/v1/admin/config/:key`
**Correct path:** `/api/v1/config/admin/:key`

Any new settings-related client code must use `/config/admin/:key`.

### 🚨 BUG #6 — Header/Footer missing on `(main)` pages

**Symptom:** Homepage, `/stays`, detail pages had no header or footer.

**Fix:** `apps/web/src/app/(main)/layout.jsx` must exist and render `<ImpersonationBanner /> <AnnouncementBar /> <Header /> <main>{children}</main> <Footer />`. The `(admin)/layout.jsx` and `(auth)/layout.jsx` have their own layouts.

**Rule:** Root `layout.jsx` only handles providers + fonts. No header/footer. Every route group has its own chrome.

### 🚨 BUG #7 — Ad-hoc placeholders breaking builds

Multiple times, `touch` created empty files that later caused `Cannot find module` or `must be a Client Component` errors. **Lesson:** verify file contents with `wc -l` after pasting. Never trust that a paste landed.

### 🚨 BUG #8 — `useId()` + remount = focus loss

Any component that generates an `id` via `useId()` will change its id if it remounts, which breaks `<label htmlFor>` association and focus. This is why the raw-HTML pattern works — it doesn't remount.

## 8. SECURITY RULES (already enforced — do not weaken)

- **All SQL is parameterized** — `$1, $2` placeholders only. No string interpolation anywhere.
- **All API inputs are validated** with Zod schemas from `@marefiyaye/shared/validators`. Route handlers call `validateBody(schema)` middleware before the controller.
- **JWT secrets ≥ 32 chars** — validated at boot by `env.js`.
- **Cookies are httpOnly + SameSite=lax** — access token in `mrf_access`, refresh in `mrf_refresh` (path-scoped).
- **`helmet`** with CSP enabled in prod.
- **`express-rate-limit`** on `/api` (100 req / 15 min by default).
- **CORS** strictly limits to `WEB_ORIGIN` + `API_ORIGIN`.
- **Impersonation requires `super_admin` role** — enforced in auth controller.
- **Passwords hashed with bcryptjs cost 12**.
- **Refresh tokens stored hashed (SHA-256)**, revocable, rotation on use.
- **Admin actions write to `audit_logs`** — actor, action, resource, before/after, IP, UA.
- **XSS protection:** React escapes by default. `dangerouslySetInnerHTML` is banned.
- **No `.env` values leak to frontend** — only `NEXT_PUBLIC_*` are exposed, and only via `env.js`.

## 16. GLOSSARY

- **God Panel** — the admin settings page where every configurable value lives
- **Config-driven** — every behavior/pricing/label is stored in the `settings` table (or `bank_accounts`, `banners`, etc.) and editable from the admin UI without touching code
- **Manual payment** — guest transfers via CBE/Telebirr/CBE Birr, uploads receipt, admin verifies
- **Hybrid stay** — a listing that supports both short-term (nightly) and long-term (monthly) rates
- **Broadcast** — a message sent from admin to guests/hosts/subset of users in a chosen delivery style
- **Delivery type** — how a broadcast is shown to the recipient (notification bell / banner bar / popup modal / sticky note)
- **Targeting** — who receives the broadcast (all / role-based / specific users)
- **Raw HTML pattern** — the workaround for the focus bug; admin modals use plain `<input>` / `<button>` / fixed divs instead of `components/ui/` primitives
- **Impersonation** — super_admin can issue a token that makes them act as another user
- **Config schema** — `packages/shared/src/config/schema/*.js`, declares every setting with type/default/labels/validator
- **The focus bug** — inputs inside modals lose focus after 1-2 chars; caused by remounting; workaround is raw HTML; root cause not yet found
- **Pattern A** — single Vercel deployment; Express runs inside Next.js API catch-all handler via `serverless-http`
